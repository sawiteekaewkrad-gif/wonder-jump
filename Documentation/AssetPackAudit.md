## 1. Pack contents

| File | Type | Purpose |
|---|---|---|
| `Assets/WonderJump/Editor/WonderJumpAssetGenerator.cs` | Editor C# (295 lines) | Builds materials and prefabs procedurally from Unity primitives |
| `Assets/WonderJump/Runtime/CharacterIdentity.cs` | Runtime C# (10 lines) | MonoBehaviour that holds `characterId` and `displayName` strings |
| `README.md`, `CLAUDE.md`, `Documentation/AssetManifest.md` | Docs | Install steps, rules, manifest |

The pack contains **no binary assets**: no FBX/GLB, textures, sprites, prefabs, scenes, audio or animation clips. Every asset is generated by a single editor menu command (`Wonder Jump → Generate Complete 3D Asset Pack`).

## 3. Defects in the generator

| ID | Severity | Location | Issue | Impact | Proposed fix |
|---|---|---|---|---|---|
| D1 | **Blocker** | L164, 178, 180, 185, 267, 290, 291 | `PrimitiveType.Cone`, `.Torus` and `.Octahedron` don't exist. Unity only has Sphere, Capsule, Cylinder, Cube, Plane and Quad | CS0117 compile error. The menu item never appears, and **any compile error blocks Play Mode for the whole project** | Add a small procedural mesh builder (cone, torus, octahedron saved as `.asset` meshes) and use it for those 7 parts |
| D2 | High | `MakeCharacter` / `Primitive()` | `CreatePrimitive` adds a collider to every child part, so each character carries 14–17 child colliders plus the root capsule as one compound collider | Edge snagging, unreliable ground checks and stomp detection, wasted physics cost | Strip child colliders inside character builds and keep only the root capsule |
| D3 | High | `GenerateItems` | Collectibles are saved with **no collider** | Pickups can't be detected | Add `SphereCollider` with `isTrigger = true` |
| D4 | Medium | `MakeMat` | Returns an existing material untouched. If the first run happened before URP was active, materials stay on `Standard` (pink in URP) for good | Silent pink materials | On re-run, re-assign the URP/Lit shader and colour. Log an error if URP is missing |
| D5 | Medium | `SavePrefab` | Every run overwrites all generated prefabs | Hand edits to generated prefabs are lost | Policy: generated prefabs are read-only. All work happens on **Prefab Variants** in a separate folder |
| D6 | Medium | Character root | Dynamic Rigidbody drives movement | Floaty platformer feel, harder to network smoothly | Replace with a kinematic character controller (see TechnicalBlueprint D-02) |
| D7 | Low | `_Sleeve` materials | Same colour as `_Outfit`, so 6 redundant materials | Minor asset bloat | Reuse the outfit material |
| D8 | Low | All prefabs | No layers/tags (Player, Enemy, Ground, Collectible, Hazard) | No physics filtering, so ground checks hit everything | Create layers in Phase 0 and assign them in the generator |
| D9 | Low | Folder setup | No assembly definitions | Full recompiles on every change; tests can't reference runtime code cleanly | Add `WonderJump.Runtime`, `WonderJump.Editor` and `WonderJump.Tests` asmdefs |
| D10 | Info | Characters | About 14–17 renderers per character (~7–9k tris from default primitives) | Fine for graybox with 2 players. Final art must be one skinned mesh with one material | Nothing for graybox |
| D11 | Info | Characters | Faces point toward −Z | The gameplay camera must sit at −Z looking +Z | Note in camera setup |

**Dependency check (CLAUDE.md rule):** the generator depends only on `WonderJump.Runtime.CharacterIdentity`, and nothing depends on the generator. Fixing D1–D4 and D7–D8 is self-contained. If `CharacterIdentity` gets a namespace or field rename, the generator (L209–211) must be updated in the same change.
